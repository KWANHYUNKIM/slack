## 발견한 버그

### 버그 1. 개발 서버(vite) 프록시에 `/reminders`, `/webhooks`, `/threads`, `/unreads`가 없음 (수정함)
- 재현: `npm run dev`로 띄운 프런트에서 메시지 더보기 메뉴로 리마인더를 만들고 "나중에 > 리마인더"를 연다. "Failed to load reminders." 표시. 같은 이유로 스레드 목록, 안 읽음 목록, 관리자 웹훅 탭도 개발 서버에서는 API 대신 index.html을 받는다(백엔드를 직접 호출하면 정상).
- 원인: `app/frontend/vite.config.ts`의 프록시 목록에 없음. `/search`도 화면 경로와 겹치는데 문서 이동 bypass가 없어 `/search?q=` 새로고침이 API로 갔다.
- 수정: `/reminders`, `/webhooks` 추가, `/threads`, `/unreads`, `/search`는 Accept: text/html이면 SPA로 bypass.

### 버그 2. 2FA를 처음 켠 직후 복구 코드를 보는 중에도 Escape, 바깥 클릭으로 창이 닫힘 (수정함)
- 재현: 새 계정 로그인 to 사용자 메뉴 to 2단계 인증 to 설정 시작 to 코드와 비밀번호 확인 to 복구 코드가 보일 때 Escape를 누른다. 창이 닫히고 코드를 다시 볼 수 없다. 재발급 흐름은 이미 막혀 있었으나 최초 설정 흐름은 막혀 있지 않았다.
- 원인: `TwoFactorDialog`가 재발급 코드(`newCodes`)만 보고 `TwoFactorSetup` 안의 복구 코드 표시 상태는 몰랐다.
- 수정: `TwoFactorSetup`에 `onCodesShown` 콜백을 추가하고 대화창이 코드 표시 중에는 Escape, 바깥 클릭, 닫기 버튼을 막는다.

## 발견했지만 고치지 않은 것 (보고만)

1. 스레드 "채널에도 보내기" 체크박스 경합(작음, UX): 답글을 보낸 직후 소켓 응답이 API 응답보다 먼저 와서 답글이 패널에 보이면, 곧이어 `ThreadPanel.handleSend`가 `setAlsoSend(false)`를 실행해 그 사이에 체크한 상태가 풀린다. 사람 손으로는 거의 안 걸리지만 자동 테스트에서는 체크가 한 번 무시됐다(테스트는 재시도로 우회).
2. 프로덕션 SPA 경로 충돌 후보(백엔드, 코드 읽기만, 미검증): `app/backend/src/app.ts`의 `spaRoutes`가 `['/files','/admin','/dms','/activity','/threads']`뿐이라, 같은 이름의 API가 있는 `/search`, `/unreads`는 프로덕션에서 새로고침(Accept: text/html, 토큰 없음) 시 index.html 대신 API 응답(401)이 올 가능성이 있다. 개발 서버에서는 위 수정으로 해결했다. 백엔드 파일이라 수정하지 않았다. 별도 파트로 확인 필요.
3. 로그인 직후 `/admin` 클릭 경합(작음): 로그인 직후 사이드바의 관리자 아이콘을 바로 누르면, 그 뒤에 "마지막 채널로 이동"이 실행돼 관리자 화면 대신 채널이 보이는 경우가 있었다(기존 admin 스펙은 `force: true` 클릭으로 가림). 주소로 직접 들어가면 문제없다.
4. DLP 규칙은 시드가 지우지 않아 테스트가 실패하면 남는다. 새 테스트는 실행마다 고유 패턴을 쓰고 끝에서 지운다.
5. 기존 `playwright.config.ts`는 백엔드를 3000, 프런트를 5173으로 고정해 병렬 개발 환경에서는 `playwright.smoke.config.ts`(서버를 띄우지 않고 `BASE_URL`에 붙음)가 필요했다. 이후 두 설정 모두 `VITE_DEV_API_TARGET`, `VITE_DEV_PORT`를 읽도록 바꿔, 개발 서버 프록시 대상과 포트를 환경 변수로 정할 수 있다(기본값은 그대로).
