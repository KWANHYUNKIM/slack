# 다국어 작성 규칙 (프런트엔드, 데스크톱, 백엔드 오류 코드)

설계는 `docs/architecture/i18n.md`를 따르고, 이 문서는 개발자가 코드를 쓸 때 지킬 규칙이다.

## 1. 키 이름
- 형식은 `<네임스페이스>:<화면>.<요소>[.<상태>]`로 쓴다. 예: `activity:page.title`, `activity:tabs.mentions`, `common:actions.save`, `errors:CHANNEL_NAME_INVALID`
- 네임스페이스는 `common`(공용 버튼과 단어), `auth`, `sidebar`, `messages`, `channels`, `activity`, `admin`, `settings`, `huddle`, `errors`(서버 오류 코드), `desktop`
- 키는 영어 소문자 camelCase로 쓰고 의미를 담는다. 화면 문구를 그대로 키로 쓰지 않는다(`"Mark all as read"`는 금지, `activity:actions.markAllRead`처럼).

## 2. 문장 작성
- 문장 조각을 이어 붙이지 않는다. 언어마다 어순이 다르기 때문이다.
  - 나쁜 예: `t('a') + name + t('b')`
  - 좋은 예: `t('messages:mentionedYou', { name })`
- 복수형과 숫자는 ICU 형식으로 쓴다. 예: `"{count, plural, one {# reply} other {# replies}}"`. 한국어는 `"답글 {count}개"` 하나로 충분하다.
- 문장 안에 링크나 굵은 글씨가 있으면 `<Trans>` 컴포넌트를 쓴다(HTML 문자열을 끼워 넣지 않는다).
- 한국어 조사(은/는, 이/가, 을/를)가 이름 뒤에 붙는 문장은 피하거나 `님`, 따옴표 등으로 조사가 필요 없게 쓴다. 예: `"{name}님이 멘션했습니다"`
- 날짜, 시간, 숫자, 목록은 번역 문자열에 직접 넣지 않고 `lib/i18n/format.ts`의 Intl 래퍼(`formatDate`, `formatRelative`, `formatNumber`, `formatList`)로 만든 값을 인자로 넘긴다.

## 3. 레이아웃
- 좌우 방향 클래스(`ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`) 대신 논리 클래스(`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`)를 쓴다.
- 방향이 있는 아이콘(화살표, 뒤로 가기)은 `rtl:rotate-180`을 붙인다.
- 사용자 콘텐츠를 담는 블록에는 `dir="auto"`를 붙인다.
- 번역문은 영어보다 30~50% 길어질 수 있다. 버튼과 탭은 고정 너비를 쓰지 말고 말줄임과 툴팁으로 처리한다.

## 4. 번역 파일
- 위치는 `app/frontend/src/locales/<locale>/<namespace>.json`
- `en`이 원문이다. 키를 추가할 때는 **`en`과 `ko`를 같은 PR에서 함께** 채운다(한국어는 1등급).
- 2등급 언어는 `en` 원문을 기준으로 번역 파일을 직접 만들고, PR에 "기계 번역 초안"이라고 표시한다. 번역 추가 절차는 `docs/architecture/i18n.md` 6-2절을 따른다.
- 서드파티 번역 데이터(emoji-mart i18n 등)도 번들에 포함한다. CDN에서 받아 오지 않는다(규칙 17).

## 5. 백엔드
- 오류 응답은 `{ error: '<영어 메시지>', code: 'UPPER_SNAKE' }` 형식으로 보낸다. 프런트는 `errors:<code>`로 번역하고, 키가 없으면 `error`를 그대로 보여 준다.
- 새 오류 코드는 `app/backend/src/errors/codes.ts`에 모아 두고, 프런트의 `errors` 네임스페이스에 en과 ko를 같이 추가한다.
- 푸시와 이메일 문구는 수신자의 `User.locale`로 서버가 번역한다(같은 번역 파일을 공유).

## 6. 검사
- ESLint 규칙(`i18next/no-literal-string`)으로 JSX 안의 하드코딩 문자열을 막는다(테스트 파일은 제외).
- CI에서 키 누락을 검사한다: `en`과 `ko`는 누락이 있으면 실패, 2등급은 경고만(`npm run i18n:check`).
- 2등급 파일도 다음은 실패한다: `en`에 없는 키, ICU 자리표시자 이름 불일치, Trans 태그 불일치, `{{` 문법, 빈 값. 규칙은 `scripts/i18n-check-lib.mjs`, 단위 테스트는 `npm run i18n:test`.
- 리뷰에서 확인한다: 새 문자열이 en과 ko에 모두 있는지, 문장 조각을 이어 붙이지 않았는지, 논리 클래스를 썼는지.
