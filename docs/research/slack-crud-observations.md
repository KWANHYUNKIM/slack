# Slack CRUD 실습 관찰 기록 (#claude-test, 2026-10-31)

방법: Claude in Chrome으로 비공개 테스트 채널 `#claude-test`(멤버는 사용자 본인뿐)에서 직접 만들고 고치고 지우며 화면과 네트워크 요청을 관찰했다. 호출은 웹 클라이언트가 `/api/<메서드>`로 보내는 POST이며, 이 문서에는 메서드 이름과 화면 동작만 적는다(요청 헤더, 토큰, 쿠키, 실제 인명은 기록하지 않음). 실습 후 모든 메시지, 답글, 리액션, 상태, 알림 일시중지를 원래대로 되돌렸다.

한계: 멤버가 본인 한 명이라 "다른 사람이 쓴 새 답글의 안 읽음 표시", 다른 사용자에게 상태가 전파되는 모습, WebSocket 프레임은 관찰하지 못했다(도구가 HTTP 요청만 제공). 이 부분은 문서 기반 추정으로 남긴다.

## 1. 메시지

| 동작 | 화면 변화 | API 메서드 |
|---|---|---|
| 보내기 | 입력창 엔터 -> 즉시 목록에 표시(낙관적 표시) | `chat.postMessage` |
| 수정 | 메시지 호버 툴바 "더 보기" 메뉴의 "메시지 편집"(단축키 E) -> 그 자리에 편집기(취소/저장 버튼), 엔터로 저장 -> 본문 옆에 "(편집됨)" 라벨 | `chat.update` |
| 리액션 추가 | 호버 툴바의 빠른 리액션 3개 + 이모지 추가 버튼. 클릭하면 본문 아래에 이모지 칩과 개수(1) | `reactions.add` |
| 리액션 제거 | 내가 단 칩을 다시 클릭하면 칩이 사라짐 | `reactions.remove` |
| 삭제 | 메뉴 "메시지 삭제..." -> 확인 대화상자("이 작업은 실행 취소할 수 없습니다", 메시지 미리보기 포함) -> 삭제 | `chat.delete` |

호버 툴바(오른쪽 위): 빠른 리액션, 리액션 추가, 스레드 답글, 전달, 저장, 공유, 더 보기. 더 보기 메뉴: 메시지 편집, 읽지 않음으로 표시(U), 저장된 항목에 추가, 리마인더 추가(하위 메뉴), 댓글에 대한 알림 끄기, 링크 복사(L), 메시지 복사, 채널에 고정(P), 앱에 연결, 메시지 삭제. 방금 단 메시지에서 위쪽 화살표는 편집이 아니라 메시지 선택으로 동작했다.

부수 호출: `megaphone.setNotificationAsSeen`(기능 안내 팁 표시 기록), `users.prefs.set`(사용 기록성 설정), `client.counts`(안 읽음 수 재조회).

시사점(클론):
- 편집 표시는 `edited` 필드(시각 포함)를 두고 UI에서 "(편집됨)" 라벨. slawk에 `editedAt`이 있는지 확인.
- 리액션은 add/remove를 별도 엔드포인트로, 같은 이모지의 개수와 내가 눌렀는지 상태를 함께 내려준다.
- 삭제 전 확인 대화상자는 필수 UX. 확인창에 대상 메시지 미리보기를 보여준다.

## 2. 스레드

| 동작 | 화면 변화 | API 메서드 |
|---|---|---|
| 스레드 패널 열기 | 오른쪽에 "스레드" 패널: 부모 메시지 + 답글 입력창 + 체크박스 "<채널>(으)로도 전송" | `conversations.history`, `conversations.replies`, `subscriptions.thread.mark`(읽음 처리), `visits.record` |
| 답글 보내기 | 패널에 답글 추가, 채널 본문의 부모 아래에 "1개의 댓글" 링크가 생김(참여자 아바타 포함). 채널 본문에는 답글 자체가 나오지 않음 | `chat.postMessage` (스레드 부모 지정) |
| "채널에도 보내기" 체크 후 답글 | 패널에서는 답글 위에 "채널에도 전송됨" 표시. 채널 본문에는 새 메시지로 나타나며 "스레드에 댓글 남김: <부모 발췌 링크>" 머리글이 붙음. 부모의 댓글 수는 2개로 증가 | `chat.postMessage` (브로드캐스트 플래그) |
| 답글 수정 | 부모와 같은 인라인 편집, "(편집됨)" 표시 | `chat.update` |
| 답글 삭제 | 확인 대화상자 후 해당 답글이 흔적 없이 사라짐(다른 답글이 남아 있을 때). 브로드캐스트 답글은 채널 본문 복사본도 함께 사라짐 | `chat.delete` |
| 부모 삭제(답글이 남은 상태) | 부모 자리에 "이 메시지는 삭제되었습니다." 자리표시자가 남고 답글은 그대로 유지됨 | `chat.delete` |
| 모든 메시지 삭제 | 스레드 카드 자체가 사라지고 빈 화면(새싹 일러스트 + "스레드 관리하기" 안내)이 나옴 | `messages.list` |

답글 메뉴에는 일반 답글이면 "이 채널에 댓글 보내기"(나중에 채널로 올리기), 이미 브로드캐스트한 답글이면 "채널에서 댓글 지우기..."(채널 복사본만 제거)가 나온다. 즉 브로드캐스트는 생성 시점 옵션이 아니라 나중에 켜고 끌 수 있는 토글이다.

### "스레드" 모아보기 화면 (사이드바 첫 항목)
- 주소는 채널 없는 `/client/<워크스페이스>`, 탭 제목 "스레드". 호출: `subscriptions.thread.getTimestamps`(스레드별 마지막 활동/읽음 시각), `users.interactions.list`, 이후 `messages.list`(카드 내용 채움).
- 스레드당 카드 하나: 위에 채널 이름과 부제(DM이면 상대, 여기서는 "나만"), 카드 안에 부모 메시지와 답글들이 인라인으로 전부 보이고, 맨 아래에 인라인 답글 입력창(체크박스 "채널로도 전송" 포함). 즉 패널을 열지 않고 카드 안에서 바로 답할 수 있다.
- 카드 안의 메시지에도 같은 호버 툴바, 수정, 삭제가 동작한다. 브로드캐스트 답글에는 "채널에도 전송됨" 머리글.
- 부모가 삭제돼도 답글이 남아 있으면 카드는 유지(부모는 자리표시자). 모든 메시지가 없어지면 카드가 사라진다.
- 내가 쓴 답글만 있는 카드는 읽음 상태(굵게/점 없음). 다른 사람의 새 답글에 따른 안 읽음 표시는 미관찰.

시사점(클론, 스펙 04 반영):
- 모아보기 카드는 "부모 + 답글 전부 + 인라인 입력창" 구조. 스펙의 "마지막 답글 몇 개만" 가정은 틀렸을 수 있다(답글이 적을 때 전부 표시. 많을 때 접기 여부는 미관찰).
- 삭제된 부모는 `deletedAt` 자리표시자로 남기고 답글은 유지. 답글이 하나도 없고 부모도 삭제되면 목록에서 제외.
- `alsoSendToChannel`은 수정 가능한 토글(올리기/내리기) API가 필요: 예) `POST /messages/:id/broadcast`, `DELETE /messages/:id/broadcast`.
- 채널 타임라인의 브로드캐스트 항목은 "스레드에 댓글 남김: 부모 발췌" 머리글.
- 읽음 처리는 스레드 패널을 열 때 `subscriptions.thread.mark` 한 번.

## 3. 상태

프로필 메뉴(좌측 하단 아바타): 이름 + 프레즌스 라벨, "상태 업데이트" 입력칸, "자신을 자리 비움으로 설정", "알림"(우측에 켜기/일시 중지됨 표시), 프로필, 환경설정 등.

| 동작 | 화면 변화 | API 메서드 |
|---|---|---|
| 상태 설정 | 입력칸 클릭 -> "상태 설정" 대화상자: 이모지 버튼(피커: 이모지/GIF 탭, 검색, 자주 쓰는 이모지) + 텍스트 입력, "기간" 드롭다운, 체크박스 "상태가 지워질 때까지 알림 일시 중지". 저장하면 아바타 모서리에 상태 이모지가 붙고 메뉴 입력칸에 이모지+텍스트 | `users.profile.set` |
| 기간 옵션 | 지우지 않음 / 30분 / 1시간 / 4시간 / 오늘(기본) / 이번 주 / 시작 및 종료 시간 선택... | (같은 호출에 만료 시각 포함) |
| 상태 수정 | 입력칸 클릭 -> 같은 대화상자가 현재 값으로 열림. 기간 드롭다운은 상대 표현이 아니라 절대 시각("오전 10:29")으로 보이고 수정 후에도 만료 시각 유지. 하단에 "상태 지우기" 버튼과 "추천 프리셋" 링크 | `users.profile.set` |
| 상태 지우기 | "상태 지우기" 클릭 -> 아바타 이모지와 메뉴 입력칸이 즉시 비워짐 | `users.profile.set` (빈 값) |

시사점: 상태는 별도 API가 아니라 프로필 필드 갱신으로 처리되며, 저장 한 번에 이모지, 텍스트, 만료 시각이 같이 간다. 수정 대화상자는 만료를 절대 시각으로 되돌려 보여주고 "상태 지우기"를 별도 버튼으로 둔다. 상태 이모지는 아바타 모서리에 붙는다.

## 4. 알림 일시 중지(방해금지)

| 동작 | 화면 변화 | API 메서드 |
|---|---|---|
| 30분 켜기 | 메뉴 "알림" > 하위 메뉴(30분 / 1시간 / 2시간 / 내일까지 / 다음 주까지 / 사용자 지정 / 업무 시간 편집)에서 "30분" -> 메뉴 우측이 "일시 중지됨"으로 바뀌고 사이드바 아바타 쪽 표시가 바뀜 | `dnd.setSnooze`, 이어서 `dnd.info`로 상태 재조회 |
| 켜진 상태 | 하위 메뉴가 "알림 재개 / 오전 10:30까지 일시 중지됨" 한 항목으로 바뀜(남은 시각을 절대 시각으로 표시) | `dnd.info` |
| 끄기 | "알림 재개" 클릭 -> 메뉴 우측이 다시 "켜기" | `dnd.endSnooze`, `dnd.info` |

시사점: 켜기, 끄기, 조회가 각각 `setSnooze(minutes)`, `endSnooze`, `info`로 분리돼 있고 켜기/끄기 뒤에는 항상 info를 다시 불러 UI를 맞춘다. 켜진 동안 메뉴에는 종료 절대 시각을 표시.

## 6. 미확인 (후속 관찰 필요)
- WebSocket 이벤트 프레임(`message_changed`, `message_deleted`, `reaction_added`, `thread_marked`, `dnd_updated` 등 실제 페이로드): 현재 도구로 볼 수 없음. REA(데스크톱 앱) 분석으로 보완.
- 다른 사용자의 답글에 의한 안 읽음 표시와 읽음 처리 시점.
- 상태 만료 시 서버가 자동으로 지우는 방식(클라이언트 타이머 여부).
- 답글이 많을 때 모아보기 카드의 접기 규칙.
