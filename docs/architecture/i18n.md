# 다국어(i18n) 설계: 한국어 우선, 전 세계 언어 지원

사용자 지시(2026-10-31 10:24): "한국말로도 할 수 있도록, 세계 언어로 할 수 있도록 전부"

## 1. 목표
- UI 전체를 번역할 수 있는 구조로 바꾼다. 화면에 박혀 있는 영어 문자열이 0개가 되게 한다.
- **한국어를 1등급**으로 둔다. 사람이 검수한 수준의 번역이고, 기본 언어 후보다.
- 전 세계 언어를 지원한다. 어떤 BCP 47 로캘이든 번역 파일 하나만 추가하면 동작하게 한다. 번역이 없는 키는 영어로 대체된다.
- 사용자가 입력하는 콘텐츠(메시지, 채널 이름, 검색)는 모든 문자 체계(한글, 한자, 아랍 문자, 데바나가리 등)에서 깨지지 않아야 한다.

## 2. 기술 선택
| 항목 | 선택 | 이유 |
|---|---|---|
| 프런트 라이브러리 | i18next + react-i18next + i18next-icu | React 생태계 표준. ICU MessageFormat으로 복수형과 성별 등 언어별 문법을 처리한다(러시아어·아랍어 복수형 6종 등) |
| 번역 파일 | `app/frontend/src/locales/<locale>/<namespace>.json` | 언어별로 나누고 필요할 때 지연 로딩한다(번들 크기 관리) |
| 날짜·숫자·상대 시간 | `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.RelativeTimeFormat`, `Intl.ListFormat` | 브라우저와 Electron에 내장돼 있어 의존성이 늘지 않는다. date-fns 포맷은 로캘 래퍼로 감싼다 |
| 정렬 | `Intl.Collator(locale)` | 채널과 사람 목록을 언어 규칙대로 정렬한다 |
| 방향(RTL) | `<html dir>`를 로캘에 따라 `rtl`로 설정하고 Tailwind 논리 속성(`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`)을 쓴다 | 아랍어, 히브리어, 페르시아어, 우르두어 |
| 언어 결정 순서 | 사용자 설정(서버) → localStorage → `navigator.languages` → `en` | 로그인 전에도 브라우저 언어로 보여 준다 |
| 서버 오류 메시지 | 응답에 `code`를 추가한다(`{ error, code: 'CHANNEL_NAME_INVALID' }`). 프런트가 code를 번역 키로 바꾼다 | 서버가 언어를 몰라도 된다. 기존 `error` 문자열은 호환을 위해 유지 |
| 사용자 설정 저장 | `User.locale`(String, nullable), `User.timeZone` | 스키마 변경이 있어 다른 스키마 파트와 순서대로 진행 |

## 4. 사용자 콘텐츠의 다국어 처리
- 채널 이름: 파트 `feat/channel-name-unicode`. 소문자로 바꿀 때 `toLocaleLowerCase`를 쓰고 NFC 정규화를 한다. 한글·한자·아랍 문자를 허용한다. 공백, 대문자 영어, 제어 문자, 이모지는 금지한다.
- 검색: PostgreSQL `pg_trgm`으로 CJK(띄어쓰기가 없는 언어)의 부분 일치를 지원한다(06 search-v2와 함께).
- 멘션 이름: 이미 유니코드 이름을 허용한다. 이름 길이 상한은 글자 수(코드 포인트) 기준.
- 메시지 렌더링: 문단마다 `dir="auto"`를 붙여, RTL과 LTR 텍스트가 섞여도 정렬이 맞게 한다.
- 폰트: 시스템 폰트 스택에 CJK와 아랍 문자 대체 폰트를 넣는다.

## 5. 데스크톱(Electron)
- 앱 메뉴, 트레이, 알림 문구도 같은 번역 파일을 쓴다(preload가 현재 로캘을 전달).
- 설치 프로그램(NSIS) 언어: 한국어와 영어 기본, 그 밖의 언어는 electron-builder가 지원하는 범위에서.

### 6-1. 2등급 진행 상태 (i18n-5)
- 진행 28/31: 완료 28개: `ja`(일본어), `zh-Hans`(중국어 간체), `es`(스페인어), `zh-Hant`(중국어 번체), `fr`(프랑스어), `de`(독일어), `pt-BR`(브라질 포르투갈어), `it`(이탈리아어), `ru`(러시아어), `uk`(우크라이나어), `pl`(폴란드어), `nl`(네덜란드어), `tr`(터키어), `sv`(스웨덴어), `da`(덴마크어), `vi`(베트남어), `id`(인도네시아어), `ms`(말레이어), `fil`(필리핀어), `hi`(힌디어), `bn`(벵골어), `th`(태국어), `nb`(노르웨이어 보크몰), `fi`(핀란드어), `cs`(체코어), `el`(그리스어), `hu`(헝가리어), `ro`(루마니아어). 네임스페이스 11개, 키는 en 전부 번역(en 대비 누락 0, 로캘당 1203키)
- 남음 3개: `ar`, `he`, `fa` (RTL, 레이아웃 점검과 함께 후속)
- 메모: `th`는 복수형 분기가 `other` 하나뿐이고, `bn`은 Intl 기본 숫자 체계(벵골 숫자)로 표시된다. E1b 새 키(errors:api 워크스페이스·조직 18개)는 i18n-5h에서 28개 언어에 추가했다.
- 상수: `app/frontend/src/lib/i18n/tiers.ts`(`TIER2_LOCALES`, 표 순서). 언어 선택 목록은 `config.ts`의 `SELECTABLE_LOCALES`.
- 남은 언어 중 `ar`, `he`, `fa`는 RTL이다. 번역을 넣으면 방향은 자동으로 `rtl`이 되지만, 레이아웃 점검은 i18n-4 기준으로 따로 한다.

### 6-2. 2등급 번역 추가 방법
1. `app/frontend/src/locales/en/*.json`의 11개 파일을 같은 구조로 `locales/<lng>/`에 만든다. 키 순서와 중첩은 원문과 같게 한다.
2. 자리표시자 `{name}`, ICU 복수형(`{count, plural, ...}`), Trans 태그(`<bold>`, `<kbd>`, `<strong>`)는 그대로 두고 문장만 번역한다. 제품명과 브랜드는 원문 그대로 둔다.
   - 복수형은 언어의 CLDR 분기를 쓴다. `ru`, `uk`, `pl`은 `one`/`few`/`many`/`other`, `it`은 `one`/`other`다. 분기 키는 `new Intl.PluralRules(locale).resolvedOptions().pluralCategories`로 확인한다(`scripts/i18n-check.test.mjs`가 검사). 검사기는 분기 개수가 아니라 인자 이름만 비교하므로 en과 분기 수가 달라도 통과한다.
   - 경계 값(0, 1, 2, 5, 11, 12, 21, 22, 111)으로 `scripts/i18n-locale.test.mjs`의 `PLURAL_CASES`에 기대값을 추가한다.
3. `app/frontend/src/lib/i18n/tiers.ts`에 `TIER2_LOCALES`에 없는 로캘이면 목록에 추가하고, 선택 UI에 보일 로캘은 `config.ts`의 `SELECTABLE_LOCALES`에 추가한다(이름은 그 언어로).
4. `cd app/frontend && npm run i18n:check && npm run i18n:test`를 통과시킨다. 2등급 누락은 경고로 나오므로 0건이 되도록 채운다.
5. 번역 파일을 읽는 로직은 지연 로딩이라 번들 크기는 늘지 않는다. 번역 없는 키는 `fallbackLng`(en)으로 대체된다.
6. 외부 번역 API와 https 의존은 쓰지 않는다. 번역은 파일로 직접 만들고 PR에 "기계 번역 초안"이라고 표시한다.

## 7. 완료 기준
- 한국어로 바꾸면 로그인부터 관리자 화면까지 영어 문자열이 하나도 보이지 않는다.
- 아랍어로 바꾸면 레이아웃이 좌우 반전되고 깨진 곳이 없다.
- `ko`, `en`, `ja`, `ar` 4개 언어로 Playwright 스모크 테스트를 통과한다. 메시지 작성·수정·삭제의 CRUD 흐름도 포함한다.
- 한국어 채널 이름 `개발팀`을 만들고, 검색하고, 멘션할 수 있다.
